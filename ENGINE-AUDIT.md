The v9 engine repair removes the movie-container AVAudioFile fallback. NativeMovieAudio asynchronously loads an AVAsset audio track, requests interleaved signed 16-bit PCM from AVAssetReader, copies bounded sample buffers into AVAudioPCMBuffer, and writes a real WAV, AIFF or CAF with AVAudioFile. The writer is released before reopening the output. Missing audio, invalid track formats, failed reader completion and empty results throw instead of producing substitute output. Cancellation is checked before setup and between sample buffers; the engine removes its staged partial file on failure. Cancellation cannot interrupt a single in-flight synchronous decoder read.

Normal image conversion, rotation, stripping and image-to-PDF retain the original pixel dimensions. Only the explicit Resize action uses maxDimension. When an offered still-image encoder is unavailable in ImageIO, all such target actions now reach the local media enhancer rather than only WebP, AVIF and BMP. The fallback receives maxDimension zero to prevent its old default 1920-pixel cap. JPEG alpha is still composited over white. PDF export rasterizes each actual PDF page with a CGPDFPage drawing transform at the requested raster size, including rotation, instead of using PDFKit thumbnail generation.

Run the conditional production-engine audit with `python3 -m unittest discover -s Tests -p test_v9_engine_audit.py -v`. It compiles the actual ConversionEngine and conversion helpers on macOS, without a mocked replacement engine. It generates a transparent 2048-pixel bitmap, validates decoded dimensions for every ImageIO-writable target, checks JPEG's white alpha background, explicit resizing and rotation, all pages of a three-page PDF, and image-to-PDF. It generates a 30-frame H.264 movie and stereo tone with native APIs, combines their tracks, tests direct movie PCM extraction and the normal audio conversion routes, checks audio duration and nonzero samples, checks output video/audio track counts and duration, decodes an output movie frame and snapshot, decodes all video-GIF frames, and checks missing-audio rejection and pre-cancellation.

This environment is Linux. Only Swift syntax parsing and source-routing assertions have run here. The macOS integration audit is explicitly skipped here and has NOT passed on a Mac. ImageIO, AVFoundation and PDFKit compile/typechecking and the generated media's actual decoding remain unverified until that test is run on macOS. Linux checks are not codec verification and do not establish that every conversion route works.

Follow-up adds a pre-install artifact validator in ConversionEngine. Native image outputs decode every frame and retain input dimensions outside Resize. PDF exports must be readable and page folders must match the source page count. WAV/AIFF/CAF/M4A outputs must contain a decodable sample buffer; MP4/MOV/M4V must have video and decode a frame. Their durations must be positive and within 250ms or 2 percent of readable input duration. Mute rejects remaining audio tracks. Enhancer-only codecs do not pretend to have Apple-decoder validation, and other regular files receive only a nonempty check here, in addition to their converter-specific checks.

Tests/v9-engine-route-inventory.json separates source/syntax pass from mac-only-untested for every covered route. Its Mac harness compiled and executed fields are both false. The pre-install validator also remains Mac-only untested.

Dimension-preference correction supersedes the earlier Resize-only description. The explicit maxDimension preference now applies to ordinary native image conversion and image-to-PDF as well as Resize, and enhancer fallbacks receive the chosen preference unchanged. A value of zero keeps the original. The artifact validator compares against the chosen capped dimensions. The Mac harness explicitly requests Original for preservation tests, 512 for a normal PNG conversion, and 1920 for Resize. Main owns migrating the old implicit 1920 default to Original and updating the reset default.

The conditional Mac harness additionally sends generated animated GIF through the production GIF-to-MP4 route if a suitable local enhancer is installed, then checks duration, video track and a decoded middle frame. This route correctly bypasses native AVAsset movie export because GIF is an image input. It remains unexecuted here and dependency-conditional.

SVG inspection found a genuine mismatch: Views lists SVG and UTType classifies it as an image, but sourceImage exclusively uses CGImageSource. ExtendedMedia's restricted demuxers do not include an SVG route. No NSImage raster fallback existed. ConversionEngine now exposes a nonisolated supportsImageInput(extension:) based on CGImageSourceCopyTypeIdentifiers rather than UTType.image. Main can gate SVG input routes with this real decoder declaration. A decode failure for SVG explains that vector-editor PNG/PDF export is needed. We do not substitute a QuickLook thumbnail or assume NSImage preview acceptance guarantees full raster support.

The Mac harness creates an actual simple SVG, logs actual ImageIO pixels and independent NSImage acceptance, and only tests raster conversion if ImageIO declares the SVG decoder. This capability investigation is conditional and unexecuted on Linux, so this change does not claim that AppKit can or cannot rasterize SVG on a particular Mac.
